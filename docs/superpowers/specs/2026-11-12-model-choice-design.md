# 등급별 모델 선택과 비용 기준 사용량 설계

- 작성일: 2026-11-12
- 상태: 브레인스토밍 합의 완료, 구현 전
- 대상:
  - comdraft: 계약, 스키마와 마이그레이션, 사용량 계산, 작성 요청 검사, 옵션 화면
  - comdraft-lambda: 단계별 모델·사고 깊이, 거절 재시도, 비용 기록과 예약, 시간 제한

## 1. 배경과 목적

지금은 모든 등급, 모든 단계가 `claude-haiku-5-5` 만 쓴다. 사용량은 입력·출력·캐시 토큰을 단순히 더해서 센다.

목표:

1. pro 는 Sonnet, max 는 Opus 까지 고를 수 있다 (5.5 기준).
2. 비싼 모델을 고르면 실제 비용만큼 사용량이 더 차감된다.

5.5 단가 (100만 토큰당, 입력 / 출력 / 캐시 읽기):

| 모델 | 입력 | 출력 | 캐시 읽기 | Haiku 대비 |
|---|---|---|---|---|
| Haiku 5.5 | $0.10 | $0.50 | $0.01 | 1× |
| Sonnet 5.5 | $2 | $10 | $0.10 | 20× |
| Opus 5.5 | $4 | $20 | $0.20 | 40× |

Haiku 5.5 는 프롬프트가 10만 토큰을 넘으면 $0.50 / $2.50 이다. 캐시 쓰기 단가는 구현 때 공식 가격표로 확인해 넣는다.

비교 도구 실행 기록(Haiku)으로 본 한 편 비용은 아래와 같다.

- Haiku: $0.013~0.040
- 같은 토큰 수로 단가만 바꾸면 Sonnet $0.26~0.80, Opus $0.53~1.61
- 출력의 8~9할은 생각(thinking) 토큰이다. 그래서 Sonnet·Opus 는 사고 깊이를 낮추고 분석 단계를 Haiku 로 고정해 비용을 줄인다.
- 이렇게 바꾼 뒤의 추정은 Sonnet 약 $0.3~0.4, Opus 약 $0.55~0.8 이다. 실측으로 확인한다.

## 2. 핵심 결정

| 주제 | 결정 |
|---|---|
| 등급별 모델 | basic: haiku / pro: haiku, sonnet / max: haiku, sonnet, opus. 기본값 haiku |
| 적용 단계 | 기획·작성·검토·고쳐 쓰기는 고른 모델, **분석은 항상 Haiku** |
| 사고 깊이 | Haiku 는 지금 그대로, Sonnet·Opus 는 단계마다 한 단계 낮춤 |
| 빈칸 채우기 | 그 초안을 마지막으로 작성한 모델. 지금 등급에서 쓸 수 없으면 쓸 수 있는 가장 높은 모델로 낮춤 |
| 요청 거절 | Sonnet·Opus 호출이 `refusal` 이면 그 단계만 Haiku 로 다시 실행. Haiku 도 거절하면 실패 |
| 사용량 단위 | 실제 비용(마이크로달러 정수). 작업마다 `used_cost`·`estimated_cost`, 등급마다 `weekly_cost_limit` |
| 주간 한도 (기준안) | basic $0.30 (Haiku 주 10편) / pro $6 (Sonnet 주 10편) / max $18 (Opus 주 15편). 실측 뒤 금액만 다시 계산 |
| 실행 시간 | Lambda 제한 7분 → **12분(720초)**. 호출 하나당 제한은 모델별로 실측 뒤 정함 |
| 화면 | 기본 옵션에 모델 줄 추가. 쓸 수 없는 모델은 잠금 표시와 함께 보여 줌 |
| 배포 순서 | 마이그레이션 → Lambda → Next.js |

## 3. 모델과 단계

### 3.1 계약 (`contract.ts`, 양쪽 저장소 공용)

- 모델 값 `GENERATION_MODELS = ['haiku', 'sonnet', 'opus']`. 실제 ID 는 `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`.
- 단가표 `MODEL_PRICES`: 모델별 100만 토큰당 입력, 출력, 캐시 쓰기, 캐시 읽기. Haiku 의 10만 토큰 초과 구간도 함께 둔다.
- `GENERATION_LAMBDA_TIMEOUT_MS = 12 * 60 * 1000`. Next.js 의 시간 초과 판정이 이 값을 따른다.
- 등급별 허용 모델은 comdraft 쪽 상수로만 둔다 (Lambda 는 등급을 판단하지 않음).

### 3.2 단계별 모델과 사고 깊이 (Lambda)

| 단계 | 모델 | Haiku 일 때 | Sonnet·Opus 일 때 |
|---|---|---|---|
| 기획 (replan 포함) | 고른 모델 | medium | low |
| 분석 | 항상 Haiku | medium | Haiku medium |
| 작성 | 고른 모델 | high | medium |
| 검토 | 고른 모델 | medium | low |
| 고쳐 쓰기 | 고른 모델 | high | medium |
| 빈칸 채우기 | 작업에 적힌 모델 | medium | low |

- 단계별 최대 출력 토큰은 지금 값 그대로 둔다.
- 작업에 적힌 모델 값이 목록 밖이면 Haiku 로 처리한다.

### 3.3 거절 재시도

- Sonnet·Opus 호출의 `stop_reason` 이 `refusal` 이면 같은 system·user 로 Haiku 를 한 번 더 부른다. 사고 깊이는 그 단계의 Haiku 값이다.
- 재시도는 단계마다 따로 한다. 다음 단계는 다시 고른 모델로 시작한다.
- Haiku 도 거절하면 지금처럼 `llm_failed` 로 실패한다.
- 서버 쪽 대체 기능(`fallbacks`)은 쓰지 않는다. Haiku 를 대체 모델로 지정할 수 없고, 단가표를 세 모델로 한정하기 위해서다.

### 3.4 실행 시간

- Lambda 시간 제한은 720초다. terraform `lambda_timeout_seconds` 와 양쪽 `GENERATION_LAMBDA_TIMEOUT_MS` 를 함께 바꾼다.
- 호출 하나당 제한(지금 180초)은 모델별 값으로 바꾼다. 값은 실측 뒤 정한다.
- 검토·고쳐 쓰기를 건너뛰는 남은 시간 기준도 그 값에 맞춘다.

## 4. 비용 기준 사용량

### 4.1 실제 사용량 (Lambda)

- 응답마다 비용을 계산한다.
  - 계산식: 입력 × 입력 단가 + 출력 × 출력 단가 + 캐시 쓰기 × 캐시 쓰기 단가 + 캐시 읽기 × 캐시 읽기 단가
  - 단가는 실제로 실행한 모델의 것을 쓴다. 거절 후 Haiku 재시도도 각자 단가로 센다.
  - 결과는 마이크로달러로 올림한다.
- `used_cost` 에 원자적으로 더한다. `used_tokens` 도 지금처럼 함께 더한다 (참고용).

### 4.2 예상량과 예약

- `estimateJobTokens` 를 단계별 입력·출력 토큰 추정으로 나누고, 단계별 모델 단가를 곱해 비용 예상량을 만든다. 분석은 Haiku 단가다.
- 빈칸 채우기도 같은 방식으로 계산한다.
- `reserveQuota` 는 `estimated_cost` 를 기록하고, 남은 비용 × `overrun_ratio` 로 허용 여부를 판정한다.
- 판정 규칙은 지금과 같다: 초과하면 `quota_exceeded`, 그 작업의 사용량은 0 으로 센다.

### 4.3 저장과 계산 (comdraft)

- `draft_prompt`:
  - `model text not null default 'haiku'` (+ 값 제약)
  - `used_cost bigint not null default 0`
  - `estimated_cost bigint`
- `quota_plan.weekly_cost_limit bigint not null`. 기준안 값: basic 300000, pro 6000000, max 18000000 (마이크로달러).
- `getJobUsage` 와 `summarizeQuota` 는 비용 컬럼으로 계산한다. 진행 중 작업은 `max(estimated_cost, used_cost)`, 나머지 규칙은 그대로다.
- Lambda 의 `getJobUsage` 와 `reserveQuota` 조회도 같은 규칙으로 바꾼다.
- 기존 작업의 비용은 마이그레이션에서 채운다: `used_cost = ceil(used_tokens × 0.26)`. Haiku 의 입력:출력이 대략 6:4 라 100만 토큰당 약 $0.26 이다. 이번 주 사용량이 갑자기 0 이 되지 않게 하기 위함이다.
- 마이그레이션 파일은 `pnpm db:generate` 로 만들고, 운영 적용은 사용자가 한다.

## 5. 등급 검사와 화면

### 5.1 서버 검사

- 작성 요청 옵션에 `model` 을 추가하고, DB 의 `user.role` 로 허용 여부를 확인한다.
- 허용되지 않으면 작업을 만들지 않고 `{ status: 'model_locked' }` 를 돌려준다.
- 빈칸 채우기는 최근 초안 작성 작업의 모델을 복사한다. 지금 등급에서 쓸 수 없으면 쓸 수 있는 가장 높은 모델로 낮춘다.

### 5.2 옵션 화면

- 기본 옵션 패널에 모델 라디오 줄을 추가한다.
  - Haiku · 기본 / Sonnet · 사용량 약 N배 / Opus · 사용량 약 M배
  - N, M 은 실측 뒤 정한다.
- 쓸 수 없는 모델은 비활성으로 두고, lucide `Lock` 아이콘과 "Pro 이상" / "Max" 표시를 붙인다.
- 모델 줄 아래 안내: "높은 모델일수록 이번 주 사용량이 빨리 줄어듭니다."
- 옵션 요약 줄에 모델을 붙인다. 예: "담백하게 · 경험 · 중간 · Sonnet"
- 고른 모델은 초안별로 기억한다. 최근 초안 작성 작업에서 불러오고, 기본값은 haiku 다. 쓸 수 없게 된 모델은 쓸 수 있는 가장 높은 모델로 보여 준다.
- 스튜디오 화면 데이터에 사용자가 고를 수 있는 모델 목록을 함께 내려준다.
- 문구는 Lingui ko/en 으로 쓴다. 테일윈드 v4, 모바일은 지금 옵션 패널 배치를 따른다.
- 사용량 숫자는 지금처럼 보여 주지 않는다. 소진 안내는 그대로다.

## 6. 검증

### 6.1 Lambda 단위 테스트

- 단계별 모델·사고 깊이 표. 분석은 항상 Haiku.
- 거절 → 그 단계만 Haiku 재시도, 호출별 단가로 비용 계산. Haiku 도 거절하면 실패.
- 비용 계산: 모델별 단가, 캐시 토큰, Haiku 10만 토큰 초과 구간, 마이크로달러 올림.
- 예상량: 단계별 입력·출력 분리, 단계별 모델 단가.
- 목록 밖 모델 값은 Haiku.

### 6.2 Next.js 단위 테스트

- 등급별 허용 모델, 쓸 수 없는 모델 낮추기.
- 옵션 검증, `model_locked`.
- 비용 기준 주간 사용량: 진행 중, 답변 대기, 사용량 초과로 실패한 작업.

### 6.3 실측 (실제 Claude, 승인 후)

- 비교 도구로 같은 케이스 2개를 Sonnet·Opus 로 돌린다 (예상 2~4달러).
- 비용, 걸린 시간, 글 품질을 본다.
- 이 결과로 정하는 것: 모델별 호출 하나당 시간 제한, 화면의 "약 N배", 등급별 주간 한도 금액.

### 6.4 화면 (로컬)

- 가짜 작성기가 모델별 가짜 비용을 기록한다.
- 모델 줄, 잠금 표시, 요약 줄, `model_locked` 안내를 등급별로 확인한다 (로컬 DB 에서 등급을 바꿔 가며).

## 7. 배포 순서

지금 Lambda 는 `used_cost` 를 기록하지 않는다. 그래서 Next.js 가 먼저 비용 기준으로 바뀌면 그 사이 사용량이 0 으로 잡힌다. 아래 순서로 배포한다.

1. **마이그레이션:** 컬럼 추가, 기존 작업 비용 채우기, 한도 값. 운영 적용은 사용자.
2. **Lambda:** `used_tokens`·`used_cost` 를 함께 기록하고, 예약은 비용으로 한다. 시간 제한 720초. terraform plan 확인 후 apply.
   - 이때까지 화면에 모델 선택이 없으므로 모든 작업은 haiku 다.
3. **Next.js:** 모델 선택 화면과 비용 기준 사용량 검사.
