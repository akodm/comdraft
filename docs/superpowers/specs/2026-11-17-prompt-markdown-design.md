# 작성 요청 마크다운 입력 설계

- 작성일: 2026-11-17
- 상태: 합의 완료, 구현 중
- 대상: comdraft (작성 요청 입력창), comdraft-lambda (작성 지시문)

## 1. 목적

AI 서비스의 입력창처럼 작성 요청에 목록, 코드 블록, 인용, 강조를 쓸 수 있게 해서 요청의 우선순위와 자료(로그, 코드)를 구조로 전달한다. 초안 품질은 해치지 않는다.

## 2. 방식 (검토한 안)

| 안                   | 내용                                                             | 결정                                           |
| -------------------- | ---------------------------------------------------------------- | ---------------------------------------------- |
| 제한된 Tiptap 편집기 | 입력하면서 서식이 바로 보이고, 제출할 때 Markdown 글로 바꿔 보냄 | **채택**. 이미 쓰는 Tiptap 이라 새 의존성 없음 |
| textarea + 미리보기  | 마크다운을 직접 치고 미리보기                                    | AI 입력창과 쓰는 느낌이 달라 제외              |

## 3. 허용 서식

- 허용: 문단, 줄바꿈, 글머리 목록, 번호 목록, 코드 블록, 인용, 굵게, 기울임, 인라인 코드
- 제외: 제목, 링크, 이미지, 표, 취소선, 밑줄, 가로줄 (붙여넣으면 글자만 남음)

## 4. 직렬화

- Tiptap Markdown 내보내기는 일반 글의 `_`, `*`, `[` 앞에 `\` 를 붙이고 `<` 를 `&lt;` 로 바꾼다. AI 가 `snake\_case` 처럼 백슬래시를 옮겨 쓸 수 있어서 **작성 요청 전용 직렬화**를 따로 둔다.
- 일반 글은 이스케이프하지 않고 그대로 둔다 (AI 가 읽는 글이라 되돌려 파싱하지 않음, 태그 모양 `<` 는 Lambda 가 따로 처리).
- 저장 형식은 지금처럼 텍스트(`draft_prompt.prompt`), DB 변경 없음. 4,000자 제한은 Markdown 글 기준.

## 5. AI 지시문 (comdraft-lambda, 한국어·영어)

`<request>` 설명에 다음을 더한다.

- 요청은 Markdown 으로 올 수 있다. 목록·인용·강조는 글쓴이가 정리한 요청의 구조이며 다룰 내용과 우선순위로 읽는다.
- 요청의 목록과 문장은 글의 절 구성이나 문장이 아니다 (request_echo 방지).
- 요청의 서식은 글의 서식 기준이 아니다.
- 요청 안 코드 블록은 글쓴이가 붙인 참고 자료다. 이해하는 데만 쓰고 글에 코드로 옮기지 않는다 (글의 코드는 커밋 diff 에서만).

## 6. 범위 밖 (이번에 하지 않음)

- 되묻기 질문 카드의 답 입력창 (textarea 유지)
- 저장소 설정의 지난 요청 기록은 지금처럼 글자 그대로 표시
