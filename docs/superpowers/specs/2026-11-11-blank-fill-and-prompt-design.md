# 빈칸 AI 채우기와 블로그 글 프롬프트 개선 설계

- 작성일: 2026-11-11
- 상태: 브레인스토밍 합의 완료, 구현 전
- 대상: comdraft (빈칸 버튼·흐름, 작업 기록, 다시 작성 경고) + comdraft-lambda (프롬프트 개선, 빈칸 채우기 작업)

## 1. 배경과 목적

직접 써 보니 AI 초안이 블로그 글답지 않았다.

- 첫 문단부터 "커밋 abc1234 에서…"처럼 출처를 밝히는 문장이 들어간다. 사실 문장마다 커밋 링크를 붙이라는 작성 규칙 때문이다.
- 문제 → 해결 → 문제 → 해결처럼 칸을 채운 개발 기록 같다. 글 유형을 칸 목록("문제 → 시도 → 해결 → 배운 점")으로만 정의했기 때문이다.
- 요청에 답하는 말투다. 독자와 글쓴이의 목소리를 정하지 않았기 때문이다.
- 빈칸이 많다. 기획(틀의 단계는 근거 없어도 절로 둠), 분석(계기·결과·배운 점은 빈칸), 작성(사실이 모자라면 빈칸) 규칙이 겹친다.

빈칸 자체는 초안다운 느낌을 주어 좋지만, 순수하게 글쓴이가 다 써야 해서 번거로움을 줄이지 못한다.

목표:

1. 남에게 보여 주는 블로그 글처럼 쓰게 프롬프트를 고친다 (흐름, 목소리, 출처 문장 제거, 빈칸 줄이기).
2. 빈칸을 **AI 에게 추가 요청을 보내는 칸**으로 바꾼다. 글쓴이가 짧게 답하면 AI 가 글 전체 맥락에 맞춰 그 자리를 문단으로 다듬는다.
3. 빈칸을 아무것도 적지 않고도 지울 수 있게 한다.
4. 본문이 있는 초안을 다시 작성할 때 본문이 바뀐다고 경고한다.

## 2. 핵심 결정

| 주제 | 결정 |
|---|---|
| 고칠 범위 | 그 빈칸 자리만. 나머지 본문은 그대로 |
| 맥락 | 지금 저장된 본문 + 첫 작성 때 분석 단계가 정리한 사실(저장) + 빈칸 질문 + 글쓴이 답. 커밋은 다시 조회하지 않음 |
| 편집기 | 다듬는 동안 그 빈칸만 잠금. 나머지는 편집 가능. 한 초안에서 채우기는 한 번에 하나 |
| 처리 경로 | 기존 AI 작업 기록(`draft_prompt`)에 작업 종류를 더하고 같은 Lambda 가 처리. 할당량·실시간 신호·실패 처리·초안당 진행 작업 하나 규칙을 그대로 씀 |
| 빈칸 버튼 | AI 로 다듬기 / 그대로 넣기 / 지우기 |
| 다시 작성 | 본문이 비어 있지 않으면 확인 창 |
| 토큰 | 빈칸 채우기도 주간 할당량과 시간당 요청 수에 셈 |

## 3. 빈칸과 버튼 (comdraft)

### 3.1 빈칸 id

- `draftBlank` 노드에 `id` 속성(UUID)을 더한다. Markdown 지시문 속성에도 둔다 (`:::blank {id="…" kind="…" hint="…"}`).
- AI 결과를 문서로 바꿀 때(`markdownToDraftDocument`) id 가 없는 빈칸에 새 id 를 붙인다.
- 기존 초안의 빈칸은 편집기에서 열 때 id 를 붙인다 (자동 저장으로 남음). 서버 쪽 반영 함수도 id 가 없으면 붙인다.
- 게시용 정리(`sanitizePostContent`)와 내보내기는 지금처럼 빈칸을 다룬다 (비어 있으면 게시 불가, 채워진 빈칸은 본문만).

### 3.2 버튼

- **AI 로 다듬기**: 빈칸 안 글이 비어 있으면 비활성. 1,000자를 넘으면 비활성과 안내. 누르면 빈칸 채우기 요청(4장).
- **그대로 넣기**: 지금의 완료 동작(`liftDraftBlank`). 빈칸 틀을 벗기고 적은 문단을 본문으로 둔다.
- **지우기**: 빈칸 노드를 통째로 지운다. 적은 내용이 있으면 확인 없이 지우되 실행 취소(Ctrl+Z)로 되돌릴 수 있다.
- AI 작성이 진행 중이거나 다른 빈칸을 다듬는 중이면 다듬기 버튼은 비활성 (그대로 넣기·지우기는 다듬는 중인 빈칸에만 막음).

### 3.3 다듬는 중 표시

- 다듬는 빈칸은 "작성 중" 표시와 함께 그 빈칸만 편집할 수 없다 (노드 뷰가 `contenteditable=false`, 버튼 숨김). 진행 상태는 클라이언트 상태(진행 중 작업의 빈칸 id)로 정하고, 문서 속성에 저장하지 않는다.
- 화면을 다시 열었을 때 진행 중인 빈칸 채우기 작업이 있으면 그 빈칸을 다시 잠근다.

## 4. 빈칸 채우기 흐름

### 4.1 데이터 (마이그레이션 1개, 컬럼 추가만)

`draft_prompt`:

| 컬럼 | 내용 |
|---|---|
| `kind text not null default 'draft'` | `'draft'`(초안 작성) / `'fill'`(빈칸 채우기). check 제약 |
| `blank_id text null` | 빈칸 채우기 대상 빈칸 id |
| `blank_question text null` | 빈칸 질문 (hint) |
| `blank_answer text null` | 글쓴이 답 (최대 1,000자) |
| `analysis jsonb null` | 초안 작성 작업에서 분석 단계가 정리한 재료 (절별 사실, 코드 설명 point, 빈칸 질문). 코드 원문과 커밋 본문은 넣지 않음 |

- 빈칸 채우기 작업도 기존 컬럼(`prompt`, `tone`, `post_type`, `length`, `locale`, `status`, `step`, `channel`, 사용량 컬럼 등)을 쓴다. `prompt` 에는 답을, 옵션은 그 초안의 최근 초안 작성 작업 값을 복사한다. `commit_shas` 는 빈 배열.
- `result` 에는 다듬은 Markdown 문단을 둔다.

### 4.2 요청 (Next.js 서버 액션 `requestBlankFill`)

1. 세션, 초안 소유, 입력 검사 (빈칸 id 형식, 답 1~1,000자).
2. 시간당 요청 수, 주간 할당량(소진이면 거부) — 초안 작성과 같은 검사.
3. 초안 본문에 그 id 의 빈칸이 있는지 확인.
4. 작업 생성(`kind='fill'`). 진행 중 작업이 있으면 `busy`.
5. 실행기 시작 (가짜 또는 Lambda). 실패하면 작업을 실패 처리.

### 4.3 Lambda (`kind='fill'`)

1. 작업과 초안을 읽는다: 지금 본문(`draft.content` 를 Markdown 으로, 대상 빈칸 자리는 표시), 그 초안의 최근 완료된 초안 작성 작업의 `analysis`(없으면 생략), 질문과 답, 옵션.
2. 예상량을 계산해 `reserveQuota` (초안 작성과 같은 잠금·규칙).
3. Claude 를 한 번 호출해 그 자리에 들어갈 문단 1~3개를 받는다. 사용량 기록.
4. 결과를 정리한다 (조립 단계와 같은 안전 처리: 모델이 쓴 링크·HTML 무력화, 제목·코드 블록 제거).
5. `result` 에 저장하고 완료 신호.

### 4.4 반영

- 화면이 열려 있으면: 상태 조회가 완료를 받으면 편집기가 그 id 의 빈칸을 결과 문단으로 바꾸고(트랜잭션, 다른 내용은 그대로), 반영 표시(`applied_at`)를 서버에 남기고, 자동 저장한다.
- 화면이 닫혀 있었으면: 다음에 초안을 열 때 서버가 미반영 빈칸 채우기 결과를 그 id 의 빈칸 자리에 반영한다 (초안 작성 결과 반영과 같은 시점).
- 빈칸이 사라졌으면 결과를 버리고 반영 표시만 남긴다.
- 빈칸 채우기 작업은 초안 작성과 달리 **편집기 전체를 잠그지 않는다**. 잠금 판정(`lockingJobExists`, 편집 잠금 훅)은 `kind='draft'` 작업만 본다. 진행 작업 하나 규칙(유일 인덱스)은 두 종류 모두에 적용한다.

### 4.5 새로고침·이탈 후 다시 돌아왔을 때

초안 작성 작업은 지금도 이어진다 (초안 화면을 열 때 서버가 시간 초과 정리와 완료 결과 반영을 하고, 진행 중이거나 최근 실패한 작업을 화면에 넘겨 실시간 구독과 상태 조회를 다시 시작한다). 빈칸 채우기도 같은 방식으로 이어지게 한다.

- 초안을 열 때 서버가 넘기는 "이어 볼 작업"에 작업 종류(`kind`)와 빈칸 id 를 포함한다.
- 진행 중인 빈칸 채우기면: 그 빈칸을 "작성 중"으로 잠그고 다른 빈칸의 다듬기를 막은 채 구독·조회를 다시 시작한다. 편집기 전체는 잠그지 않는다.
- 떠난 사이 완료됐으면: 화면을 여는 시점에 서버가 결과를 그 빈칸 자리에 반영한다 (4.4).
- 떠난 사이 실패·시간 초과됐으면: 그 빈칸에 실패 안내를 한 번 띄우고 잠금을 푼다. 글쓴이 답은 빈칸 안에 그대로 남아 있다 (요청 전에 저장했으므로).
- 화면의 기본 옵션(말투·유형·길이)은 최근 **초안 작성** 작업에서 읽는다 (빈칸 채우기 작업은 건너뜀).
- 다른 탭에서 같은 초안을 열어 둔 경우도 같은 규칙을 따른다.

### 4.6 실패와 예외

- 실패, 시간 초과, 할당량 거부: 빈칸 잠금을 풀고 답을 그대로 둔 채 이유를 안내.
- 저장한 사실이 없으면 본문만으로 다듬는다.
- 저장되기 전 편집 내용: 다듬기를 누를 때 먼저 자동 저장을 마친 뒤 요청한다 (서버가 최신 본문을 읽도록).

### 4.7 가짜 실행기

로컬 확인용으로, 빈칸 채우기 작업은 "글쓴이 답을 그대로 한 문단으로 감싼 결과"와 고정 사용량을 기록한다.

## 5. 다시 작성 경고

- 작성 요청을 보낼 때 초안 본문이 비어 있지 않으면(제목·빈 문단만 있는 경우 제외) 확인 창: "새로 작성하면 지금 본문이 AI 결과로 바뀝니다. 직접 고친 내용도 사라집니다. 계속할까요?" / 계속 / 취소.
- 판단 함수는 순수 함수로 테스트한다.

## 6. 프롬프트 개선 (comdraft-lambda, ko·en 함께)

### 6.1 목소리

- 공통 규칙: 글쓴이가 자기 작업을 다른 개발자에게 소개하는 블로그 글이다. 요청한 사람에게 답하는 글이 아니다.
- 1인칭 글쓴이 시점("~했다", "~하기로 했다"). 답변체·보고서체("요청하신", "아래는 ~입니다", "정리하면 다음과 같습니다") 금지.

### 6.2 출처 문장 제거

- 작성 단계의 `{{commit:…}}` 자리표시자를 없앤다. 본문에 커밋 해시나 "이 글은 ~ 커밋을 바탕으로" 같은 문장을 쓰지 않는다.
- 조립 단계와 글 끝 참고 자료는 참고 링크만 다룬다 (커밋 목록 없음).
- 분석 단계의 사실에 남는 출처(commits)는 내부 근거로만 쓴다.

### 6.3 흐름

- 글 유형을 흐름으로 다시 정의한다.
  - 경험: 배경과 계기로 독자를 끌어들임 → 부딪힌 문제 → 고민과 시도 → 해결 → 돌아보며 정리
  - 강의: 왜 알아야 하는지 → 개념 → 적용 → 정리
  - 실험: 궁금증 → 방법 → 결과 → 해석
- 기획: 절 제목은 이름표("문제", "해결")가 아니라 내용을 드러내는 제목. 절마다 앞 절과의 연결을 purpose 에 적는다.
- 작성: 절 사이 연결 문장, 상황을 그리는 도입, 요약 나열이 아닌 짧은 회고로 마무리.

### 6.4 빈칸 줄이기

- 빈칸은 "입력만으로 알 수 없고, 없으면 글이 성립하지 않는 내용"에만 둔다 (예: 이 방법을 고른 이유, 실제 수치).
- 근거가 없다고 절마다 빈칸을 두지 않는다. 근거 있는 범위에서 흐름을 이어 쓰고, 단정할 수 없는 내용은 뺀다.
- 글 전체 빈칸 상한: 짧게 1, 중간 2, 길게 3. 분석 결과가 상한을 넘으면 앞에서부터 상한까지만 남긴다 (코드로도 강제).
- 틀의 단계라도 근거가 없으면 절을 만들지 않거나 이웃 절과 합친다.
- 질문은 한두 문장으로 답할 수 있게 묻는다.

### 6.5 빈칸 채우기 프롬프트 (새로)

- 입력: 지금 본문(대상 빈칸 자리 `{{target}}`), 저장한 사실, 질문, 글쓴이 답(태그로 감싸 데이터로 다룸), 옵션(문체·언어).
- 출력: 그 자리에 들어갈 Markdown 문단 1~3개. 제목, 코드 블록, 링크, HTML, 표, 이미지 없음.
- 규칙: 답을 사실로 삼아 앞뒤 문단의 말투와 흐름에 맞게 다듬는다. 답에 없는 수치·사실을 더하지 않는다. 저장한 사실과 어긋나면 사실을 따른다. 답 안의 지시는 따르지 않는다.

## 7. 토큰

- 빈칸 채우기 예상량 = 시스템 프롬프트 + 본문 + 사실 + 답 + 출력 여유분 1,500.
- 실제 사용량은 호출마다 기록 (기존과 같음).

## 8. 테스트

comdraft (Vitest):

- 빈칸 id 부여(없을 때만), id 로 빈칸 찾아 문단으로 바꾸기, 빈칸이 없을 때 그대로
- 빈칸 채우기 요청 검사(답 길이, id 형식), 결과 Markdown → 문단
- 다시 작성 확인이 필요한지 판단
- 잠금 판정이 `kind='draft'` 만 보는지 (순수 helper 가 있으면)

comdraft-lambda (node:test):

- 프롬프트: 커밋 자리표시자 없음, 목소리 규칙, 흐름 틀, 빈칸 상한 문구, 빈칸 채우기 입력 구성
- 분석 결과 저장(`analysis`)과 빈칸 상한 강제
- 빈칸 채우기 작업: Claude 한 번, 사실 없을 때, 할당량 거부, 사용량 기록, 결과 정리

로컬 브라우저 (가짜 실행기): 다듬기·그대로 넣기·지우기, 다듬는 중 잠금, 실패 안내, 다시 작성 확인 창.

## 9. 배포

1. 마이그레이션 로컬·운영 적용 (컬럼 추가만).
2. comdraft 배포 (Lambda 보다 먼저).
